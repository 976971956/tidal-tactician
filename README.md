# 走江踏浪 · 智能推演器

玩家同步《疯狂水世界》中的真实局面。工作台复演攻击、掉落和移动，并给出一条推荐路线。首次打开显示空棋盘，可以直接录入自己的局面。通过「存档 → 重置局面 → 载入示例」可以试用示例。

## 本地启动

需要 Node.js 22.12 或更新的 22.x 版本。

在 macOS 的 Finder 中双击 `启动推演器.command`。脚本会在缺少依赖时安装依赖，构建应用并打开浏览器。使用时保留终端窗口，按 Control+C 停止服务。重复双击会打开已运行的推演器。

手动启动开发服务可运行以下命令。

```bash
npm ci
npm run dev
```

访问终端显示的本地地址。要检查生产构建与离线缓存，先执行 `npm run build`，再执行 `npm run preview`。

## 使用方式

- 点任意灰格，添加、删除或编辑僵尸和道具。大型邪祟以点击格为左下角，向上和向右各展开一格。放在第一排时，上方两格显示在棋盘外，随下一次前进进入棋盘。「批量编辑」能一次覆盖 30 格。空格用 `.`，普通僵尸用 `5` 或 `5/20`，特殊僵尸用 `S5/20`，追远密卷用 `B`，血瓷瓶用 `R`，同格用 `+` 连接。批量文本在大型邪祟的左下格输入 `L71`（71 血示例）。
- 在「编辑」模式点黄色区或休息区格子可以添加、调整攻击力或删除伙伴。切回「推演」，先点起点再点目标。休息区伙伴可上阵到空格，也可直接与伙伴区内同角色、同攻击力的伙伴合成，结果留在伙伴区。桌面支持鼠标拖动。
- 「同步资源」修改饮料、积分、符咒和回合。使用火焰符时点击灰格选择整列。冰冻符立即生效，并在后续正常回合消耗剩余冻结时长。
- 「分析下一步」执行 3–7 回合的束搜索。先搜常规路线，再尝试符咒。推荐可以对照前后棋盘、伤害与路线，确认后执行其中第一步。达到搜索深度与清除全部已知僵尸有不同状态提示。搜索有宽度和模拟步数上限，剪枝后可能遗漏走法。未知刷怪须继续同步。
- 「存档」支持手动快照、JSON 文件导入导出、粘贴完整 JSON 和复制局面文本。自动保存带 30 步撤销、重做历史。换设备或域名时可用 JSON 搬迁进度。
- 「规则设置」可调整伤害、道具目标和移动、攻击顺序、碰撞、合成、冻结和底线。旧存档会更新仍用旧版默认值的攻击顺序和符纸配置。也可点「载入微信默认规则」后保存。休息区容量可按账号解锁的格数调整。

## 微信版核对记录

游戏内说明确认，放置、移动、合成或交换消耗一瓶饮料，所有上阵伙伴先攻击，然后邪祟前进一格。邪祟踏入上阵区时结束本局。同级同角色可合成，攻击力翻倍，最高十级。按初始攻击力 1 翻倍九次，推演器默认上限为 512。秦璃攻击整列邪祟，李追远的单张符纸只能打一个目标，可以命中血瓷瓶或追远密卷。休息区满时无法获得新伙伴。

通过 Mac 的启动脚本打开网页后，可在首页直接按 `⌘V` 粘贴完整的微信对局截图，也可以点「载入微信实局 → 选择截图」。识别使用 Mac 的 Vision 和 Swift 工具。图片留在本机。核对格子和资源后点「确认载入截图」，可以用「撤销」恢复原棋盘。

「载入之前的 4535 分快照」可打开之前记录的棋盘。微信实局中，休息区两格已解锁，第三格提示购买战令解锁。第 5–6 排、第 3–4 列有一只画面显示 71 血的大型邪祟，当时火焰符为 0，冰冻符为 1。记录用画面血量代填初始血量，击杀分需按实局修正。当前对局停在原处，未推进回合。

根据交换前后的实战截图，默认按秦璃先攻、李追远逐张结算符纸来复演。每张符纸只打一个目标，击杀后剩余符纸可打同列后方。李追远的 1、2、4、8 及以上攻击力分别按 1、2、2、4 张计算。该局原有密卷随邪祟下移一排。血瓷瓶暂按相同方式移动，道具遇到冰冻时是否停步可在规则设置校准。

第 1 排的新邪祟和道具由实战刷新。推演结算的是已录入的棋盘，实战刷新后可以粘贴新截图继续。

## 项目结构

| 路径 | 内容 |
| --- | --- |
| `src/game/model.ts` | 棋盘、规则、伙伴操作与示例 |
| `src/game/combat.ts` | 回合结算、道具、符咒与越线判定 |
| `src/game/search.ts`、`search.worker.ts` | 合法操作枚举、状态去重、风险评分和后台搜索 |
| `src/game/history.ts`、`storage.ts` | 历史、存档验证、批量文本格式 |
| `src/App.tsx`、`Board.tsx`、`Editors.tsx`、`Analysis.tsx` | 工作台、棋盘、编辑器、建议与预览 |
| `public/`、`scripts/offline.mjs` | 本地素材、PWA 清单与生产离线缓存 |
| `tests/` | Vitest 规则测试与 Playwright 浏览器测试 |

## 测试

```bash
npm test
npm run build
npx playwright install chromium webkit
npm run test:browser
```

Playwright 用桌面 Chromium 和 iPhone 13 触摸配置下的 WebKit 运行生产页面。测试覆盖 40 格渲染、触摸编辑、点选交换、推荐预览和执行、撤销、重做、存档及离线缓存。

## HTTPS 部署

发布到 GitHub Pages 时，在仓库的「Settings → Pages」把发布来源设为「GitHub Actions」。「Deploy to GitHub Pages」工作流会在推送到 `main` 后自动构建并发布，也可从 Actions 手动启动。网页版可手动录入、推演和导入 JSON。微信截图可先在 Mac 本地版识别后导出 JSON。

在 Vercel 导入项目所在的 Git 仓库，根目录选到包含 `package.json` 的目录，框架选 Vite。Netlify 同样以这个目录作为构建根目录。两者均用 Node.js 22，构建命令 `npm run build`，发布目录 `dist`，无需环境变量或后端。也可先本地构建，再上传整个 `dist/` 到支持 HTTPS 的静态托管。部署后用 iPhone Safari 打开 HTTPS 地址，可从分享菜单添加到主屏幕。首次联网访问并完成缓存后，生产页面和推演 Worker 可离线启动。

[Vercel 的 Vite 文档](https://vercel.com/docs/frameworks/frontend/vite) · [Netlify 框架设置](https://docs.netlify.com/start/framework-setup/)
